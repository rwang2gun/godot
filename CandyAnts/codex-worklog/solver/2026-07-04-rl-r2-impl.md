## 구현 (tools/solver/rl/{mdp,train}.py — 엔진/PlanRunner/기존 게이트 무변경)

### mdp.py — 문법 r2.1 (r1.1 경로 보존: `StageMDP(grammar=...)` 버전 인자, 기본값 r1.1)
- **전역 어휘(P2)**: `global_vocab()` = SkillRegistry 메타 전 스킬 11종(정렬) + `w_max=33/h_max=18/hp_max=7`
  (campaign_manifest 등재 스테이지 **전수 스캔 파생**, 하드코딩 0; 초과 스테이지 등재 시 명시 에러 =
  silent 확장 금지). **어휘 digest** = 시맨틱 전부(스킬 순서·트리거·격자 크기·at_frame bin)의 sha256.
- **sum-type 액션(P3)**: `target_kind{ant,cell}` 1급 head(스킬 메타가 유일 유효값 = 마스킹으로 강제) +
  트리거 `{ant_reaches_x, picked_ge, at_frame}`(직교 — cell도 전 트리거 유효, PlanRunner 시맨틱 그대로) +
  `at_frame` 양자화 head(`AT_FRAME_QUANT=300`f, bins 0..6900, 마스크 상한=at_frame_cap=train_deadline).
- **행 head 이원화**: 전역 row head(h_max+1) 공유 — ant 마스크 = {any}∪surface rows(r1.1 계승),
  cell 마스크 = 스테이지 전 행. col/param head는 스테이지 W/hp 마스크.
- **r2 슬롯 = 전역 고정 max_len**(obs 차원 스테이지-불변 — flat_dim 816). 실제 plan 길이는 **인벤토리
  동적 마스크**가 제한(스텝0 SUBMIT 마스킹 유지, 소진 시 SUBMIT만).
- encode/decode r2 = JSON lowering 명문화 + 라운드트립. **digest 3종**: layout/mask(per-stage)/vocab(전역).

### train.py — 체크포인트 2모드(P1) + CNN 정책(P2) + verify-r2 + 등가성 러너
- **정책**: 공유 CNN(5ch conv×2 + AdaptiveMaxPool 4×4 — 가변 H×W → 고정 임베딩) + flat 816 → MLP 128 →
  전역 head. 전 파라미터 shape 스테이지-무관(`_model_cfg` = ckpt 호환 계약).
- **ckpt**(`data/solutions/rl_ckpt/stageNN_seedS.r2.pt`, `candyants-rl2-ckpt-v1`): 직렬화 전수 =
  policy+optimizer + torch RNG(사용 RNG 전수) + entropy 카운터 + SIL 내용·순서 + baseline + 세그먼트/사슬
  카운터 + digest 3종 + model_cfg·dtype + chain. **`--resume-ckpt`** exact(stage/layout/mask/seed/shape
  전부 일치, 클리어 세그먼트 resume=no-op 터미널) / **`--transfer-ckpt`** curriculum(가중치만 이월,
  레이아웃·마스크 면제 + 전역 어휘 digest fail-closed, 미클리어 ckpt 거부, entropy·SIL·baseline 리셋,
  RNG=새 seed). fail-closed 음성 5종 실증(미클리어 transfer/타 스테이지 resume/seed 불일치/shape 불일치/
  동일 스테이지 transfer).
- **r2 산출물 = stageNN.rl2.json**(r0/r1 rl.json과 분리·영구 보존): per-seed 커맨드 병합 누적(lockfile
  직렬화 — 병렬 사슬 레이스 차단), 결측 seed=FAIL 집계(predicate는 클리어 수만), chain(mode/구간
  카운터/ckpt sha)·ckpt_loaded/saved provenance 기록.
- **verify-r2**: R1 게이트 전체 계승(pinned 예산·라운드트립·replay ×2·trace 재생·live preflight) +
  **마스크-표현 가능성**(라운드트립보다 강한 검사 — 인벤토리 초과·cap 초과·비-surface row 거부) +
  ckpt/사슬 무결(파일 sha 재계산·내부 digest·**직전-산출물 출처 대조 = cherry-pick 차단**·mode별 계약) +
  curriculum manifest 정합(등재+순서) + `config.max_batches` 금지. **음성 실증 7종**(N1 predicate/N2 chain
  mode/N3 ckpt sha/N4 off-grid/N5 max_batches 위장/N6 비-pinned seed/N7 인벤토리 초과) 전부 FAIL 검출 +
  복원 PASS.
- **`--accept-resume-equiv`**: 2N 무중단 vs N+ckpt+resume+N — 정책 파라미터 **비트 동일** + 배치별 meanR
  곡선 일치 + 에피소드 수 일치. wall 조기중단 비활성(배치 수만 종료).

## Acceptance 실측 (plan §R2)

1. **재개 등가성(P1)**: pinned `--accept-resume-equiv --grammar r2.1 --stage 11 --seeds 0 --envs 4
   --max-batches 6 --shaping trace --train-deadline 4500 --sil` → **PASS**(파라미터 비트동일 + 곡선 10배치
   일치, greedy-clear 경계 케이스까지 재현 — A는 batch 10 클리어, B는 6에서 저장·재개 후 동일 batch 10 클리어).
2. **curriculum 사슬(P4)**: seed {0,1,2}별 독립 커맨드 사슬 S11(scratch)→S12(transfer)→S13(transfer),
   공통 구간 예산(20000eps/1800s/trace/SIL/td4500). → **FAIL 0/3 (정직 박제 — plan §R2 정직 경계
   "전이가 안 되는 것도 결과")**. 상세:
   - S11 scratch: **3/3 클리어**(160/160/1280 eps — r1.1 재생성과 동일 스케일. r2 CNN도 S11 무난).
   - S12 transfer: **seed2만 클리어(2400 eps — r1.1 from-scratch seed2의 3200보다 빠름 = 전이 가속
     단일 사례)**. seed0/1 FAIL이되 **bestR 3.729/3.717 = 샘플링에서 클리어 에피소드 발견**(3-blocker
     구조 정합) — greedy 수렴만 실패(280/305배치 소진). r1.1 from-scratch는 seed0 클리어(4320eps)였으므로
     r2 문법 확장(트리거 3종·전역 12-slot skill head·kind head)의 credit assignment 부담 + S11 전이
     bias가 수렴을 늦춘 것으로 진단. 예산 병목 아님(공정 재실행에서 280배치 = r1.1과 등가).
   - S13 transfer(seed2): FAIL bestR **0.660 — from-scratch 대조(3-seed 전부 0.660)와 동일 고원**.
     S13은 carry-연쇄 다단이라 trace-shaping 신호가 부족(R1-스윕 박제 재확인). **전이 유무가 S13 고원을
     못 바꿈** — curriculum만으론 S12→S13 갭 불가, R3 후보(trace-피드백 refinement·dense shaping) 근거.
3. **어휘 증명(P3)**: ⓐ `--coverage-r2` = known S11·S12(ant)+S19(cell, sand_mound at_frame 0) 인코딩→
   디코드→엔진 클리어 **PASS**(4/4·5/5·5/5). ⓑ S19 from-scratch pinned 3-seed = **PASS 3/3**
   (80/80/160 eps — **cell-target 배치를 무힌트 학습으로 발견**, 어휘 확장 실증).
4. **verify-r2**: stage11 **PASS**(3/3·사슬/ckpt 무결·replay ×2) + stage19 **PASS**(3/3) + **음성 실증

## 이슈/발견
- **I-R2-1 (torch 스레드 오버서브스크립션)**: 병렬 3사슬(각 4 env) + torch 기본 intra-op 스레드(24)로
  S12 세그먼트 배치 처리량 ~20x 붕괴(1800s에 20배치 vs r1.1 단독 270배치) → seed0/1 transfer가 예산
  잠식 상태로 FAIL(bestR 0.231, 길이-1 국소최적) = **공정 시험 아님**. 조치: `_torch()`에
  `torch.set_num_threads(1)` 고정(모델 소형 — 멀티스레드 이득 0, reduction 순서 고정으로 결정론 강화)
  + **사슬 순차 재실행**(R1 acceptance와 동일 무경합 조건). 오염된 S12 seed0/1 FAIL 항목은 재실행이
  병합-대체.
- **I-R2-2 (rl2 병합 레이스)**: 병렬 per-seed 사슬이 같은 rl2.json을 read-merge-write — lockfile
  (O_CREAT|O_EXCL) 직렬화로 유실 차단.
- **I-R2-3 (ckpt 크기)**: ckpt 개당 ~2.5MB(policy+optimizer+RNG 전수) — 7개(S11×3·S12×3·S13 seed2)
  ≈ 18MB 커밋. verify-r2 사슬/출처 검증이 ckpt 파일 실존·sha에 의존하므로 산출물로 커밋(사용자가
  git-lfs/프루닝 원하면 후속).
- **I-R2-4 (merge 리팩터 잔재 NameError)**: `_merge_write_r2` 분리 때 `have_all` 참조가 마지막 로그
  줄에 잔존 — 산출물 기록(write) **후** 크래시라 데이터 무결엔 무해했으나 exit≠0으로 **S12 seed2
  클리어 후 S13 세그먼트가 미실행**되는 사슬 중단을 유발. 수정 + seed2 S13 단독 재개로 복구.
  교훈: 병렬 장기 러닝 중 코드 수정 시, 러닝이 로드한 코드와 워킹트리 드리프트 주의.
