# 솔버 지식 볼트 (CBR/EBL, Obsidian 구조)

각 **액션(스킬) 사용 시 고려할 요소**를 위키링크로 연결된 지식 그래프로 관리한다. 지금까지 `model.py`/
`solve.py` 주석·휴리스틱에 흩어져 있던 솔버 지식을, **해석가능·성장 가능한 단일 SoT**로 외부화한다.

## 왜 (de-risk 2026-06-24 교훈)
4a 실증: "학습 전술로 일치 후보를 boost"는 휴리스틱이 이미 같은 순서를 내므로 **롤아웃을 못 줄였다**.
진짜 레버는 (a) 휴리스틱이 낭비하는 **형제 후보 pruning**, (b) 휴리스틱이 모르는 지식. 둘 다 "지식을
구조화해 솔버가 추론에 쓰게" 해야 나온다 → 기계 매칭 라이브러리가 아니라 **지식 볼트**.

설계 원칙(사용자 2026-06-24):
- **스스로 답을 찾는다**: 레벨마다 손 시드 ✗. 볼트의 요소를 적용해 후보 생성·pruning·우선순위를 도출.
- **레벨 바뀔 때마다 재검증 ✗**: 한 번 학습한 요소는 노트로 영속 → 새 레벨은 매칭·적용만(백지 재탐색 탈피).

## 구조
- `crises/<crisis>.md` — **위기 상황**(솔버 검색의 진입점). diagnose가 검출하는 실패 패턴 + 그걸 푸는 도구·
  요소로 링크. frontmatter `detect:`가 diagnose 신호와 연결(상황 인덱스).
- `skills/<skill>.md` — 한 스킬의 용도·고려 요소·타이밍·상호작용·실패 모드·learned_from(스킬 인덱스).
- `factors/<factor>.md` — 스킬을 가로지르는 **고려 요소**(천장 인지·물 우선·backpath 등). 코드 근거 인용.
- `subgoals/<subgoal>.md` — 서브골(반전·상승·간격 건넘·귀환)과 그걸 푸는 스킬.
- `stages/<stage>.md` — 레벨이 행사한 스킬·요소(증거 노드, learned_from 역링크).

## 솔버 검색 흐름 (위기 인덱스, 사용자 2026-06-24)
**발생한 위기 상황 → 링크된 도구 조회 → 해결.** "스킬·상황 이중 인덱싱"의 상황 측:
1. `diagnose()`가 관측 궤적에서 위기 신호를 낸다(물 익사 가장자리·carry 갇힘·낙하사·사탕 미도달).
2. 그 신호로 `crises/` 노트를 조회 → 노트가 링크한 **도구(skill)·요소(factor)**를 얻는다.
3. 그 도구·요소로 후보를 **생성·우선순위·pruning** → 적은 롤아웃으로 해결.
4. 새 위기·새 해결을 만나면 crisis/factor 노트를 추가(성장). 레벨 바뀌어도 재탐색 아닌 **조회·적용**.

## 노트 규약
- frontmatter `type`(skill/factor/subgoal/stage) + 메타. 본문에 `[[wikilink]]`로 연결.
- 요소는 **반증 가능·코드 근거**로 적는다("S17 col17 천장無 → saved 0 무한왕복" 식 실측).
- 미존재 `[[link]]`도 OK(앞으로 쓸 노트 표시).

## 솔버 연결(로드맵)
- 단기: 볼트 = 솔버 지식 SoT. `model.py` 휴리스틱은 볼트 요소를 *구현*하고, 왜인지는 볼트가 설명.
- 중기: `knowledge.py`가 볼트를 파싱 → 요소를 후보 **생성 prior + pruning 규칙**으로 솔버에 주입.
  지식 추가 = 마크다운 편집(코드 수정 아님). 새 레벨 해결 시 새 요소 노트를 추가(성장).
- 검증: `transfer-bench`(4a 인프라)로 "볼트 적용 ON vs OFF" 롤아웃·provenance 측정은 그대로 유효.
