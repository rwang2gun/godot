## 0.7. 피드백 #1 — "남는 개미 역할 없음" : exact-fit 개미경제 (이미 해소)

**검증된 설계 (사용자 의도 + 코드/데이터 실측 일치)**: `총마리 = candy_hp + (해를 위해 영구 소비되는 정착 개미)`. 모든 개미가 정확히 한 역할(운반 or 도구) → 의미 없이 방황/소멸하는 "남는 개미"가 없다. hp는 전 스테이지 5로 낮춰 플레이타임·유실 최소화.

- **소비하는 스킬(②정착·이탈)** = `blocker`·`floater`(탭하면 영구 고정, 집에 안 감). **소비 안 하는 스킬**(①푯말/③무장/④장치) = 일하고 계속 걸음.
- 9스테이지 전부 `총 = hp + 정착개미`로 딱 맞음: S2(7=5+floater+blocker)·S5(6=5+floater)·S9(6=5+blocker), 나머지 5=5+0.
- 코드 뒷받침(`scripts/world/Home.gd`): **빈손 귀가 → 3초 후 재등장(왕복 재시도)**, **사탕 소진 후 빈손 귀가 → 집에서 은퇴**(`SavedState`=queue_free). 클리어=조각 기반(`ScoreSystem.is_cleared = candy_hp==0 && in_transit==0`).
- **가이드 함의**: 카드/어포던스는 이 설계를 **거스르지 말고 강화** — "모든 개미가 소중해, 함부로 잃지 마" 톤. 도구 개미(blocker/floater)도 "역할을 다하고 남는다"로 긍정 프레이밍.

**⚠ 잔여 리스크 2건 (라이트 유저 관점) — 결정됨 2026-06-07**:
1. **exact-fit 취약성**: 딱 맞아서 — 개미가 *사탕 줍기 전* 유실(물·기절)되거나 예산 밖 정착 스킬을 쓰면 **hp가 0에 못 닿아 soft-lock**(클리어 불가). 재등장은 *빈손 귀가*만 커버, *유실 개미*는 못 살림. → **결정: 현행 유지(안전망 미도입).** 유실 최소화 레벨 설계 + 재시작으로 흡수. (향후 실플레이 데이터로 재검토 가능 — 본 리스크는 박제만.)
2. **S1 blocker 예산 밖 → 해소됨(2026-06-07, codex R1 HIGH)**: S1은 `총5 = hp5`인데 blocker가 인벤토리에 있어 **쓰면 운반자 4<5 → 클리어 불가**. 어포던스가 `can_apply`만 보고 blocker를 유효 타깃으로 반짝여 초등학생을 첫 판부터 함정으로 유도(codex HIGH). → **결정: S1에서 blocker 제거**(`stage01.tres` available=`[climber]`, inventory=`{climber:5}`). S1은 climber 튜토리얼이라 blocker 불요. `CampaignS1ClearTest` saved=5/5 PASS 확인(carry-consume 1:1 실증). blocker 첫 등장은 **S2**(거긴 `총7=hp5+floater1+blocker1`로 예산 안).

## 0.8. 피드백 #2 — 인게임 시각 어포던스 설계 (스킬 직관성)

**근본 원인(코드 확인)**: 스킬 활성 방식이 4종 혼재인데(③개미탭-무장 / ②개미탭-정착 / ①땅탭-푯말 / ④땅탭-장치), **"이 스킬이 개미를 탭하는지 땅을 탭하는지"를 알려주는 시각 신호가 없다.** 유일한 공통 신호가 "스킬 아이콘=마우스 커서"뿐이고, 미리보기는 `PlacementPreview`의 3종(`sand_mound·builder·bridge`)만, 그것도 커서 셀 아닌 "최근접 개미" 기준이라 부정확.

### 0.8.1 핵심 규칙 (아이에게 가르칠 한 줄)
> **반짝이는 걸 탭한다.** 개미가 반짝이면 개미를, 바닥 타일이 반짝이면 바닥을. **커서는 결과물 모양**이다.

### 0.8.2 입력모델 → 어포던스 매핑 (사용자 아이디어 + 코드 검증)

| 입력모델 | 스킬 | 커서 | 반짝임 = 탭 대상 | 비고 |
|---|---|---|---|---|
| **③ 무장** | climber · bridge · builder | **스킬 아이콘** | **개미**(적격만) | 탭 시점 ghost **없음**(낭떠러지/벽에서 자동 발동이라 위치가 나중에 결정). → `PlacementPreview`에서 bridge/builder 제거 |
| **② 정착·이탈** | blocker · floater | **최종 배치 형태(반투명)** — blocker=팔 벌린 벽 / floater=낙하산 분배자 | **개미**(적격만) | 반투명 폼은 raw 커서가 아니라 **타깃(최근접 적격) 개미 위에 스냅** → "이 개미가 이렇게 된다" |
| **① 푯말** | sand_mound · basher · cutter · digger | **푯말**(`skill_sign_board.png` + 스킬 아이콘) | **surface 타일**(실제 설치 가능 셀) | 반짝일 셀 = **`SignPlacement.resolve_surface_install_cell`이 valid 반환하는 셀**(점유 거부 + 아래 64칸 스냅 = 지면 위 빈 셀). ⚠ 트리거 규칙(`_ant_at_cell`) 아님 — 그건 "걷는 개미가 나중에 발동"이고, 글로우는 "지금 클릭 성공" 셀이어야 함(codex R1 MEDIUM) |
| **④ 장치** | leaf_jump | **점프대 장치** | **surface 타일** | `LeafJumpPad` 직접 설치. 동일 `SignPlacement` API + **기존 pad 있는 셀 제외**(`_leaf_jump_pad_exists`). 미리보기 = 점프대 고스트 |

### 0.8.3 다듬기 5건 (구현 전 결정/주의)
1. **적격(can_apply) 게이팅** — 글로우는 *적격* 대상만(`Skill.can_apply(ant)`가 10종 모두 존재). 부적격 개미는 안 반짝 = "왜 안 되지"를 시각으로 답함. (①푯말의 타일 글로우는 개미 아닌 "표면 여부" 기준.)
2. **글로우 인프라 신설** — 현재 개미/타일 하이라이트 시스템 **없음**(`Motion`은 fade/pop tween만). → **결정: 외곽선 셰이더(2026-06-07).** 개미 스프라이트·surface 타일에 적용할 재사용 `outline.gdshader`(외곽선 폭·색·펄스 알파 uniform) 신설. 색 토큰은 `Tokens`/`UI_GUIDE` 팔레트 사용. 적격=강조색 펄스, 부적격=무표시. (라이트 유저 명확성 우선 — modulate-only보다 형태 경계가 또렷.)
3. **`PlacementPreview` 리팩터** — 현 `PLACEMENT_SKILLS=[sand_mound,builder,bridge]`는 입력모델 혼재. bridge/builder(③)를 탭-타임 고스트에서 빼고(무장이라 호도), 미리보기 개념을 ①④ surface-glow + 푯말/장치 고스트로 재배치.
4. **입력 모드 분기** — 마우스=hover 커서 / 터치=hover 없음(글로우가 주 신호, 반투명 폼은 "마지막 터치 최근접 개미"에 표시) / 패드=`VirtualCursor`가 커서 대행. **글로우는 3모드 공통.**
5. **②반투명 폼 앵커** — floater/blocker 최종형 미리보기는 타깃 개미에 스냅(§0.8.2 비고)해야 의미가 읽힘.

### 0.8.5 카테고리 규칙 = 단일 SoT (신규 스킬 확장성) — CRITICAL
어포던스·커서·글로우·라우팅은 **스킬별 하드코딩이 아니라 "입력모델 카테고리" 단일 매핑에서 파생**한다. 신규 스킬 추가 = **카테고리 1줄 선언**이면 글로우/커서/라우팅이 자동 동작.

- **SoT (신설)**: `scripts/core/SkillAffordance.gd` —
  - `enum Category { ANT_ARMED, ANT_SETTLE, SIGN, DEVICE }` (= DOMAIN_MAP §2.1 입력모델 ③②①④)
  - `SKILL_CATEGORY: { skill_id → Category }` (10종 전부)
  - `CATEGORY_AFFORDANCE: { Category → { glow_target: ANT|SURFACE, cursor_kind: ICON|SETTLE_FORM|SIGN|DEVICE } }`
- **기존 분산 SoT 흡수(이중 SoT 제거, CLAUDE.md 규칙)**: `SkillSign.SIGN_SKILLS`(①) · `LeafJumpPad`/`REUSABLE_SIGNS`(④) · `PlacementPreview.PLACEMENT_SKILLS` · `SkillToolbar._try_assign` 푯말/탭 분기 → **전부 카테고리 SoT 조회로 대체**. 라우팅도 카테고리가 결정.
- **확장 계약(가드 테스트)**: `SkillRegistry.SKILL_SCRIPTS`의 모든 스킬은 `SKILL_CATEGORY`에 항목이 있어야 한다. 누락 = 테스트 실패(신규 스킬이 카테고리 선언을 빠뜨리면 시끄럽게 깨짐). → CLAUDE.md "새 스킬 = SkillRegistry preload 1줄" 옆에 **"카테고리 1줄"이 짝**으로 추가됨.
- **문서 미러**: DOMAIN_MAP §2.1 입력모델 4분류가 이 코드 SoT의 인간용 미러. 카테고리 추가/이동 시 둘 다 갱신.

### 0.8.4 교육 효과
- "개미 반짝 vs 타일 반짝"이 ②③(개미) ↔ ①④(땅)의 4종 혼란을 **2지선다로 축소**.
- 커서가 결과물(아이콘/정착폼/푯말/점프대)이라 "이 스킬이 뭘 하나"를 탭 전에 텔레그래프.
- 적격 게이팅이 "아무 개미/아무 땅에나 안 된다"를 비언어로 학습.
- 인트로 카드(§2~4)의 입력모델 배지와 **같은 시각 어휘**를 공유(카드에서 배운 걸 인게임 글로우가 재확인).

### 0.8.6 신규 스킬 = 가이드 에셋 계약 (카테고리 파생) — CRITICAL
카테고리 SoT(§0.8.5)에 더해, **카테고리별 필요 가이드 에셋을 계약으로 명시**한다. 신규 스킬 추가 시 그 카테고리가 요구하는 에셋이 자동 검출·요청되어, 에셋 누락 채로 머지되지 않는다. (1인 개발 + AI 자산 모델, `ASSET_PRODUCTION_NEEDS.md` 연계)

- **공통(전 스킬)**: 툴바/칩 아이콘 `assets/icons/skills/{id}.png` + 커서 `assets/icons/skills/cursors/{id}.png` + `Strings.skill_label(id)` + 카드 설명 카피 `guide.skill.{id}`.
- **카테고리 추가 요구**:
  - **ANT_SETTLE(②)**: 반투명 **정착폼 스프라이트**(커서 프리뷰 = 최종 배치 모습. blocker=팔 벌린 벽 / floater=낙하산 분배자).
  - **DEVICE(④)**: **장치 스프라이트**(점프대 류).
  - **SIGN(①)/ANT_ARMED(③)**: 공통 아이콘으로 충분(추가 없음 — 푯말은 `skill_sign_board.png`+아이콘 합성).
  - **입력모델 배지 4종**(카테고리당 1, 공유 — 스킬별 아님).
- **계약 SoT**: `SkillAffordance.CATEGORY_GUIDE_ASSETS: { Category → [required asset/copy keys] }`. 카테고리 SoT 옆에 둬 단일 출처.
- **가드 + 자동 요청**:
  - `tests/SkillGuideAssetContractTest`: 등록 스킬 전체가 카테고리 요구 에셋/카피를 만족하는지 검사 → 누락 시 **fail + 무엇이 없는지 출력**.
  - `scripts/tools/report_skill_guide_assets.py`: **`--report-check`(verify/CI 기본)** = 누락분을 `docs/ASSET_PRODUCTION_NEEDS.md`에 **먼저 멱등 기록**(무엇을 그려야 하는지 자동 안내) → **그 다음 누락 시 비정상 종료**. 요청 생성과 게이트 실패가 **같은 필수 경로**(codex R1 MEDIUM 대응 — `--check` 단독은 요청 없이 실패만 했음). `--check`는 읽기전용 옵션.
- **확장 계약 한 줄**: CLAUDE.md "새 스킬 = SkillRegistry preload 1줄 + 카테고리 1줄" 옆에 **"카테고리 에셋 계약 충족(또는 ASSET_PRODUCTION_NEEDS에 요청 기록)"**이 짝.

## 1. ⚠ 사전 정합성 노트 (혼란 관리)

가이드 계획을 라이브 데이터에 맞추기 위해 `data/stages/stage0*.tres`를 직접 확인한 결과, **`LEVEL_REDESIGN_STATUS.md` 서술과 라이브 `available_skills`가 일부 어긋난다.** 본 가이드 계획의 "신규 스킬"은 **라이브 `.tres`를 SoT로** 삼는다(아래 §4 표는 라이브 기준).

| 스테이지 | LEVEL_REDESIGN 서술 | **라이브 `available_skills`(SoT)** | 차이 |
|---|---|---|---|
| S2 오르막 | climber + floater + **distributor** | `[climber, floater, blocker]` | distributor는 F-3에서 **은퇴**(floater에 흡수). distributor 카드 만들지 말 것 |
| S6 땅굴 | digger + **floater** | `[digger, climber]` | 동반 스킬이 floater가 아니라 **climber**. F-14 보정과도 교차 → 구현 확인 필요 |

> **조치**: 카드 문안 확정 전, 각 스테이지의 `available_skills`·`skill_inventory`와 실제 지형(해저드 인스턴스)을 한 번 더 대조해 "신규 요소"를 확정한다. 본 문서는 라이브 `.tres` 스냅샷(2026-06-07) 기준이며, 레벨이 추가 개정되면 §4 표를 동기화한다.

## 2. 가이드 시스템 설계 (Architecture)

### 2.1 컴포넌트: `StageIntroCard`

새 `Control` 노드 1개. **`StageDialog`(결과 카드)의 형제 패턴을 그대로 복제**한다 — 검증된 race/pause 안전 패턴을 재사용해 신규 위험을 최소화.

- 위치: `scripts/ui/StageIntroCard.gd` + `scenes/ui/StageIntroCard.tscn`. `Main.tscn`에 `StageDialog`와 나란히 인스턴스(또는 스테이지 씬 공통 HUD 계층).
- `process_mode = PROCESS_MODE_ALWAYS` — 게임이 멈춰도(트리 pause) 카드 입력은 동작(StageDialog와 동일).
- 시작 시 `visible = false`, `StageRunner`/`SceneFlow`가 `show_intro(stage_data)` 호출로 노출.
- **재사용 자산**: `Motion.fade_in/caPop`(등장 모션), `Tokens`(색), `scripts/ui/atoms/CButton`(시작/스킵 버튼), `Chip`/`SkillSlot`(스킬 칩), `Strings.t(...)`(문안), `EventBus.sfx_request`(`dialog_open` 등 기존 sfx id 재사용).

### 2.2 카드 레이아웃 (1장 구성)

```
┌─────────────────────────────────────┐
│  스테이지 N · "첫 마실"               │  ← 타이틀 (display_name)
│                                       │
│  🎯 목표 한 줄                        │  ← goal (목표 카피)
│                                       │
│  [🧗 벽 오르기]  ← 신규 스킬 칩(1~2)  │  ← skill chips (아이콘+라벨+입력모델 배지)
│  "탭하면 능력을 들고 걷다가 벽에서     │  ← 신규 스킬 설명 1~2줄
│   자동으로 올라가요"                   │
│                                       │
│  ⚠ (해저드 있을 때만) 소다물 = 닿으면 │  ← hazard 경고 (조건부)
│     즉시 잃어요                        │
│                                       │
│        [ 시작 ]        [ 건너뛰기 ]    │  ← CButton ×2
└─────────────────────────────────────┘
```

- **입력 모델 배지**: 각 스킬 칩에 "어떻게 쓰나"를 아이콘/색으로 표기(§3.2의 4분류). 플레이어가 가장 많이 틀리는 지점("개미를 탭? 아니면 땅에 표지판?")을 카드에서 1차 해소.
- 카드 높이는 신규 요소 수에 따라 가변(0~2 스킬 + 0~1 해저드).

### 2.3 표시 흐름 / 통합 seam

현재 `StageRunner._ready()`는 `_spawner.start()`를 **즉시** 호출해 개미 스폰·타이머가 바로 시작된다(`scripts/core/StageRunner.gd:80`). 인트로 카드는 **스폰/타이머 시작을 카드 닫을 때까지 게이트**해야 한다.

권장 seam(둘 중 택1, 구현 단계에서 결정):

1. **트리 pause 방식(간단)**: 카드 `show_intro()` 시 `get_tree().paused = true` → 카드는 `PROCESS_MODE_ALWAYS`라 입력 받음 → "시작" 누르면 `paused = false`. `StageRunner.start()`는 그대로 두되, 스폰 첫 틱이 pause로 지연됨. ※ 단, `_ready`에서 동기 emit되는 degraded 경로(`AntSpawner.start` total<=0) 주의 — StageRunner의 기존 ordering 가드 확인.
2. **명시적 start 게이트(견고)**: `StageRunner`가 `start()`를 `_ready`에서 분리 → `SceneFlow`(또는 카드)가 `intro_dismissed` 시그널 후 `StageRunner.begin()` 호출. 카드 없는 스테이지/테스트는 즉시 `begin()`. **헤드리스 테스트 친화적**이라 이 방식 권장.

> 결정 포인트: 헤드리스 테스트(`run_test.py`)는 카드를 띄우지 않고 즉시 `begin()` 해야 회귀가 안 깨진다. → 방식 2 + "테스트/플레이테스트 진입은 인트로 스킵" 플래그.

### 2.4 데이터 소스 (카드 문안을 어디에 두나)

3안 비교. **B안(별도 가이드 리소스) 권장.**

| 안 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A | `StageData`에 `intro_title/intro_body/intro_hazards` export 추가 | 스테이지와 1:1, 레벨툴에서 편집 | StageData 비대화, 게임플레이 데이터와 카피 혼재 |
| **B (권장)** | `data/guides/stageNN_guide.tres`(신규 `StageGuideData` 리소스) — 신규 스킬 id 배열 + 카피 key 배열 + 해저드 플래그 | 관심사 분리, 카피만 독립 수정, 누락 시 카드 생략 | 파일 1개 추가/스테이지 |
| C | `Strings.gd`에 `guide.stageNN.*` key 직묶음, 카드가 stage.id로 조회 | 인프라 0 추가(Strings만) | 신규 스킬 칩 목록을 코드/Strings에 중복 표현, 데이터-뷰 결합 |

- 어느 안이든 **카피 문자열 자체는 `Strings.gd`** 에 둔다(`guide.s1.goal`, `guide.s1.climber_desc` …). 리소스는 "어떤 key를 보여줄지"의 메타만.
- 스킬 칩은 `Strings.skill_label(id)` + `SkillToolbar.ICONS[id]`를 재사용 → 칩 라벨 중복 정의 없음.

### 2.5 재방문 / 스킵 정책

- **기본(1차)**: 진입마다 표시. "건너뛰기" 버튼 + Esc로 즉시 닫기(StageDialog의 `_unhandled_input` Esc 패턴 복제).
- **옵션(후속)**: `SaveData`에 `seen_intro[stage_id]` 플래그 → 이미 본 스테이지는 자동 스킵(또는 "다시 보지 않기" 체크박스). 최소 범위에선 **미구현 권장**(클리어 후 replay 시 빠른 스킵 버튼으로 충분).

### 2.6 입력 모드(mouse/pad/touch) 대응

- 조작 안내 문구는 `InputModeTracker`의 현재 모드에 맞춰 분기(기존 `InputHintLabel` 패턴 재사용). 예: mouse="클릭", touch="탭", pad="A 버튼".
- "시작"/"건너뛰기" 버튼은 `CButton`이라 3입력 모두 포커스/활성 지원(기존 PauseMenu·StageDialog와 동일).

### 2.7 테스트 훅

- `StageIntroCard`에 검사 inspector: `is_showing()`, `shown_skill_ids()`, `intro_dismissed`(시그널). StageDialog의 `is_next_disabled()`류 패턴.
- 회귀: ① 카드 표시 → "시작" → `StageRunner.begin()` 1회 호출 단언 ② 헤드리스/플레이테스트 진입 시 카드 스킵(스폰 즉시) ③ 신규 스킬 id가 stage `available_skills`의 부분집합인지(가이드-데이터 드리프트 가드) ④ Esc/건너뛰기 dismiss.
- **드리프트 가드(중요)**: §1 같은 어긋남 재발 방지 — "가이드가 광고하는 스킬 ⊆ stage.available_skills" 단언 테스트를 두면 레벨 개정 시 카드가 자동으로 검증됨.

## 3. 가이드해야 할 요소 인벤토리 (What to teach)

### 3.1 글로벌 기본기 — **S1에서 1회 집중**

| 요소 | 가르칠 내용 | 비고 |
|---|---|---|
| **목표** | 사탕(Candy)을 조각내 집(Home)으로 운반. 사탕 HP만큼 운반 성공하면 클리어. | 4-카운터의 'saved'가 목표치 |
| **4-카운터(HUD)** | 사탕HP / 운반중(in_transit) / 귀가(saved) / 잃음(lost). | `ADR-002`, HUD 좌상단 |
| **조작 = 스킬 부여** | 스킬 선택 → 개미/땅에 적용. 입력 모드별 표기. | §3.2 입력모델로 연결 |
| **개미 자동 보행** | 개미는 알아서 걷고, 벽 만나면 돌아선다. 플레이어는 "능력만 부여". | Lemmings 핵심 멘탈모델 |
| **release rate / 일시정지 / 배속** | HUD 스테퍼로 스폰 속도 조절, Space=일시정지, 배속 버튼. | `ReleaseRateStepper`, `PauseBtn`, `SpeedBtn` |
| **별점** | saved 비율로 별 1~3개. | `star_thresholds`, StageDialog |

### 3.2 입력 모델 4종 — **"어떻게 발동하나"가 가장 중요한 학습 축** (DOMAIN_MAP §2.1)

각 신규 스킬 카드는 그 스킬이 어느 모델인지 **배지로 명시**한다. 캠페인이 4종을 모두 가르친다:

| # | 입력 모델 | 발동법 | 캠페인 도입 스킬 | 첫 등장 |
|---|---|---|---|---|
| ① | **푯말 설치형** | 땅(타일)에 푯말 설치 → 도착한 개미가 그 자리서 작업 | sand_mound · digger · basher · cutter | S5 |
| ② | **정착·이탈형** | 개미를 탭 → 그 자리 영구 고정·이탈 | blocker · floater | S2(blocker·floater) |
| ③ | **무장·자동발동형** | 개미를 탭 → 능력 들고 걷다 조건 위치서 자동 발동 | climber · bridge · builder | S1(climber) |
| ④ | **장치 설치형** | 땅에 물리 장치 설치 → 장치가 도착 개미에 작용(재사용) | leaf_jump | S8 |

> 핵심 UX 가설: 플레이어가 가장 많이 막히는 지점은 "개미를 눌러야 하나, 땅을 눌러야 하나". 카드에서 이 한 가지를 ②③(개미 탭) vs ①④(땅 설치)로 명확히 구분해 주면 대부분의 초기 혼란이 해소된다.

### 3.3 스킬 10종 중 캠페인 8종(+blocker/leaf_jump) 효과

## 4. 스테이지별 가이드 계획 (S1~S8)

> "신규" = 그 스테이지에서 **처음 등장**해 카드가 강조할 요소. "복습"은 카드에서 생략하거나 1줄 미만. 카피는 초안(확정 시 `Strings.gd`로 이관).

### S1 · "첫 마실" — climber · **모든 글로벌 기본기**
- **라이브**: `available=[climber]` (인벤토리 climber5), 5마리, hp5, 90s, ★0.6/0.8/1.0. (blocker는 §0.7 리스크2 해소로 제거 — S2가 첫 등장.)
- **신규**: 목표·4-카운터·조작·자동 보행·release/pause·별점(글로벌 1회) + **climber(③ 무장형)**. 단일 스킬이라 카드가 climber + 글로벌 기본기에 집중.
- **카드 제목**: 스테이지 1 · 첫 마실
- **목표 카피**: "사탕을 한 조각씩 집으로 옮겨요. 5조각을 다 옮기면 성공!"
- **스킬 카피(climber)**: "개미를 탭하면 *벽 오르기*를 들고 걸어요. 벽을 만나면 스스로 타고 올라가요."
- **입력 강조**: ③ 무장 = "개미를 탭" / 땅이 아니라 개미.

### S2 · "오르막" — floater · 기절 규칙
- **라이브**: `available=[climber, floater, blocker]`, 7마리, hp5, 100s.
- **신규**: **floater(② 정착·이탈형)** + **기절(Stun) 규칙**. climber 복습.
- **목표 카피**: "높이 올라간 사탕을 가지러 가요. 그런데 내려올 때가 위험해요."
- **스킬 카피(floater)**: "개미를 탭해 *낙하산*을 정착시키면, 지나가는 동료들이 낙하산을 받아 높은 곳에서도 안전하게 내려와요."
- **규칙 카피(기절)**: "⚠ 너무 높이서 떨어지면(6칸↑) 개미가 기절해 사라져요. 낙하산이 있으면 괜찮아요."
- **입력 강조**: ② 정착 = "개미를 탭하면 그 자리에 머물러요"(③ 무장과 대비 — 같은 '개미 탭'이지만 결과가 다름).
- ⚠ §1: distributor 언급 금지(은퇴). floater가 분배 역할.

### S3 · "사탕 호수" — bridge · 소다물 해저드
- **라이브**: `available=[bridge]`, 5마리, hp5, 110s.
- **신규**: **bridge(③ 무장형)** + **소다물(즉사 해저드)**.
- **목표 카피**: "사탕 호수 건너편의 사탕을 가져와요. 물에 빠지면 안 돼요."
- **스킬 카피(bridge)**: "개미에게 *다리만들기*를 주면, 낭떠러지에 닿았을 때 스스로 수평 다리를 놓아요. 한 번 놓으면 모두가 건너요."
- **해저드 카피**: "⚠ 소다물에 닿으면 그 즉시 잃어요. 다리로 건너세요."
- **입력 강조**: ③ 무장(climber와 같은 계열 — "탭하고 걷다 자동 발동").

### S4 · "계단 공사" — builder
- **라이브**: `available=[builder]`, 5마리, hp5, 110s.
- **신규**: **builder(③ 무장형, 대각 계단)**. bridge(평지)와 대비.
- **목표 카피**: "높은 단 위의 사탕으로 올라가는 계단을 만들어요."
- **스킬 카피(builder)**: "*경사면*을 주면 낭떠러지에서 비스듬한 계단을 쌓아 올라가요. 다리는 평평하게, 계단은 위로."
- **입력 강조**: ③ 무장. "bridge=수평 / builder=대각" 1줄 비교(복습 연결).

### S5 · "막대과자 탑" — sand_mound · **첫 푯말 설치형** · floater 복습
- **라이브**: `available=[sand_mound, floater]`, 6마리, hp5, 120s.
- **신규**: **sand_mound(① 푯말 설치형 — 입력 모델 전환점!)**. floater 복습(귀가 강하).
- **목표 카피**: "막대과자 사다리를 세워 탑 위 사탕에 닿아요. 내려올 땐 낙하산으로."
- **스킬 카피(sand_mound)**: "이제는 *땅에 푯말*을 놓아요. 막대과자 사다리가 세워지고, 무리가 타고 올라가요."
- **입력 강조(중요)**: ① 푯말 = **"개미가 아니라 땅(기둥 세울 자리)을 탭"** — ②③(개미 탭)에서 처음으로 바뀌는 지점이므로 카드가 명확히 대비.

### S6 · "땅굴" — digger · climber 복습
- **라이브**: `available=[digger, climber]`, 5마리, hp5, 120s.
- **신규**: **digger(① 푯말, 수직 아래 굴착)**.
- **목표 카피**: "땅을 파고 내려가 지하의 사탕을 가져와요."
- **스킬 카피(digger)**: "땅에 *땅파기* 푯말을 놓으면, 도착한 개미가 아래로 굴을 파요. 한 번 뚫린 굴은 모두가 써요."
- **입력 강조**: ① 푯말(sand_mound 복습) + "방향: 아래로".
- ⚠ §1·F-14: 라이브 동반 스킬은 **floater가 아니라 climber**(인벤토리 climber5). 따라서 "낙하산으로 안전 강하" 카피는 **틀림** — 굴 깊이가 기절 임계 미만이거나 climber로 되올라오는 구조일 가능성. **카드 확정 전 stage06 지오메트리(공동 깊이)·기절 발생 여부 실기 확인 후** 안전/귀환 카피 결정. climber는 "복습"이라 카드에서 1줄 이하.

### S7 · "옆파기" — basher
- **라이브**: `available=[basher]`, 5마리, hp5.
- **신규**: **basher(① 푯말, 수평 앞 굴착)**.
- **목표 카피**: "앞을 가로막은 과자 벽을 옆으로 뚫어 길을 내요."
- **스킬 카피(basher)**: "벽 앞 땅에 *벽 부수기* 푯말을 놓으면 수평 통로를 파요. digger는 아래로, basher는 앞으로."
- **입력 강조**: ① 푯말 + "방향: 앞으로"(digger와 대비).

### S8 · "박하 덤불" — cutter · leaf_jump · 끈끈이 해저드
- **라이브**: `available=[cutter, leaf_jump]`, 5마리, 60s.
- **신규**: **cutter(① 푯말, 식물 전용)** + **leaf_jump(④ 장치 설치형 — 4번째 입력 모델!)** + **끈끈이(3초 정지 해저드)**.
- **목표 카피**: "박하 덤불을 자르고, 끈끈이를 점프대로 건너 사탕에 닿아요." (시간 60s — 가장 빠듯, 카드에서 "서둘러요" 톤)
- **스킬 카피(cutter)**: "*식물 자르기*는 식물 벽 전용이에요(흙 벽엔 안 통해요)."
- **스킬 카피(leaf_jump)**: "*나뭇잎 점프대*는 땅에 놓는 장치예요 — 개미가 도착하면 폴짝 띄워줘요. 여러 번 써요."
- **해저드 카피**: "⚠ 끈끈이를 밟으면 3초 멈춰요(잃지는 않아요). 점프대로 건너뛰세요."
- **입력 강조**: ④ 장치 = "땅에 놓는 점프대"(① 푯말과 미묘하게 다름 — 장치는 재사용). 신규 요소가 3개라 **카드가 가장 빽빽** → 카피 우선순위: 끈끈이 위험 > 점프대 사용법 > cutter.

### S9 · "종합 과자점" (선택) — 신규 없음
- **라이브**: `available=[bridge, basher, blocker, sand_mound]` — 전부 기존.
- **신규 0**. 인트로 카드는 **피날레/복습 톤**(선택): "지금까지 배운 모든 걸 써요. 다리·벽 부수기·막대과자·길 막기를 조합해 마지막 사탕을 가져오세요." 신규 스킬 칩 없음 → 카드 생략도 가능.

## 5. 카피 작성 원칙

1. **1장에 신규만.** 복습 요소는 카드에서 빼거나 1줄 비교로만. 카드가 길어지면 안 읽는다.
2. **입력 모델을 먼저.** "무엇을 하나"보다 "어디를 탭하나"(개미 vs 땅)를 우선 — 초기 혼란의 80%.
3. **동사 중심 짧은 한국어.** 게임 톤(사탕·개미·과자) 유지. 1스킬 = 1~2줄.
4. **해저드는 ⚠로 시각 분리.** 손실 위험은 항상 눈에 띄게.
5. **대비로 가르치기.** "bridge=수평/builder=대각", "digger=아래/basher=앞" 같은 짝 비교가 단독 설명보다 잘 박힌다.
6. **모든 문안은 `Strings.gd`.** `guide.sN.*` 네임스페이스. 씬 하드코딩 금지(프로젝트 규칙).
