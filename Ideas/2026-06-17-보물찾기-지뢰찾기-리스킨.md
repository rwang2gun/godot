# 아이디어 1 — 보물 발굴 게임 (지뢰찾기 반전형)

🌿 구체화 · 2026-06-17

> 가제 **TreasureDig** (한글명 미정 — "보물 발굴단" 등 후보).
> 지뢰찾기의 추론 재미를 보존하면서, 8살 아이도 즐길 수 있도록 "폭탄→보물"을 **반전 구조**로 풀어낸 고고학 발굴 퍼즐.

## 한 줄
흙을 곡괭이로 부숴 단서를 모으고, **추론으로 찾아낸 보물을 한정된 발굴권으로 조심스럽게 캐내는** 캐주얼 발굴 퍼즐.

---

## 왜 "반전형"인가 (핵심 통찰)
"폭탄→보물"을 글자 그대로 *"보물을 찾아라"*로 바꾸면 지뢰찾기의 **추론 코어가 깨진다**. 추론은 `숫자 = 주변 위험 개수` + `위험 칸은 절대 건드리면 안 됨` 구조에서만 나오기 때문.

그래서 **보물 = 지뢰**(부수면 안 되는 칸)로 두고, 깃발 꽂기(추상적 가설 표시)를 **"발굴 브러시로 직접 캐내는 보상 행동"**으로 승격시킨다. 추론은 그대로 보존되면서 행동이 직관적·즐거워지고, 즉사도 사라진다.

---

## 핵심 메커니즘 (완전 명세)

### 칸의 두 종류
- **흙/돌 칸 (= 안전칸)**: 곡괭이로 부수면 사라지고 **숫자(주변 8칸 중 보물 칸 개수)**가 드러난다. `0`이면 인접 흙칸이 연쇄 개방(캐스케이드).
- **보물 칸 (= 지뢰)**: 숫자를 표시하지 않는 "센서 대상". 곡괭이로 부수면 **파손**(점수 감소), 발굴 브러시로 캐면 **온전한 보물 획득**.

### 두 가지 도구
| 도구 | 자원 | 흙칸에 쓰면 | 보물칸에 쓰면 |
|---|---|---|---|
| **곡괭이** | 무제한·빠름 | 단서 공개(0이면 캐스케이드) | **파손** + 점수 감소 |
| **발굴 브러시** | **발굴권 N회 한정** | 발굴권 1 낭비(흙 제거, 단서는 공개 — 실수 복구 가능) | **온전 획득** + 도감 등록 |

- 기본 도구 = 곡괭이. 화면 툴바의 큼직한 **도구 토글 버튼**으로 전환(아이패드 롱프레스 회피).
- **발굴권 카운터**를 HUD에 크게 노출(예: 🪶 × 8).

### 핵심 결정 루프
1. 곡괭이로 흙을 부숴 **숫자 지도**를 드러낸다.
2. 숫자로 **보물 위치를 추론**한다(노-게스 보장 → 항상 논리로 확정 가능).
3. 확신한 보물에만 **한정된 발굴권**을 써서 온전히 캐낸다.
4. **발굴권 소진** 또는 **모든 보물 해결** 시 종료 → 온전히 캔 보물로 점수·별점 산정.

> 발굴권 제한이 "모든 칸을 안전하게 발굴만 하는 거북이 플레이"를 막고, 추론으로 효율을 내도록 강제한다. (지뢰찾기의 "지뢰 개수" 긴장을 자원 형태로 부활)

### 여러 칸 보물 (멀티셀)
- 한 보물이 인접 여러 칸 차지(큰 항아리=2칸, 유물 뼈대=3~4칸 등).
- **숫자 계산**: 보물 칸 하나당 +1(2칸 보물은 인접 흙칸에 최대 +2 기여) → 표준 카운팅·솔버 호환.
- **발굴**: 칸을 하나씩 캐서 전체를 드러낸다(조금씩 모습이 드러나는 발굴 쾌감). 모든 칸 온전히 캐야 **완전 획득**; 일부라도 곡괭이로 부수면 **파손 상태**로 도감 등록.

### 실패가 없는 종료
게임오버·강제 재시작 없음. 보물 파손·발굴권 소진은 **점수/별점 손실로만** 반영. 항상 끝까지 플레이 가능.

## 지뢰찾기 재미 → 이 게임에서 어떻게 보존되나
| 지뢰찾기 재미 | 이 게임에서 |
|---|---|
| 추론(코어) | 숫자로 보물 위치 확정 — **그대로** (노-게스 보장) |
| 캐스케이드 개방 | 곡괭이 0칸 연쇄 개방 — **그대로** + 흙먼지 파티클·사운드 |
| 위험 vs 정보 긴장 | 즉사 대신 **발굴권 자원 + 파손 점수**로 재구성 |
| 깃발(가설 표시) | **발굴 브러시로 직접 캐내는 보상 행동**으로 승격 |
| 숙련 곡선 | 숫자 패턴 읽기 + 발굴권 배분 전략 |
| 깔끔한 승리 조건 | "보물 다 캐기" — 흙 전부 부술 필요 없어 판이 짧음 |

## 8살 완화 설계 (코어 유지, 부하·벌칙만 ↓)
- **노-게스 + 첫 탭 안전**: 항상 논리로 풀리는 보드만(강제 추측 0). 공정성 1순위.
- **패배 없음**: 점수·별점만.
- **작은 보드·짧은 판**: 5×5 / 보물 2~3개로 시작.
- **화려한 캐스케이드·발굴 연출**: 파티클 + SFX + 보석 반짝.
- **숫자 + 색/아이콘 보강**: 0~3 중심, 안전=초록 글로우 / 보물 근접=노랑·빨강 + 탐지기 아이콘.
- **큼직한 탭 타깃 · 도구 토글 버튼**.
- **수집 도감/박물관**: 캔 보물을 전시 → 손에 잡히는 수집 동기.

## 시스템 상세
- **입력**: 도구 토글(곡괭이/발굴) + 탭. 화면→격자 좌표 변환(`cell = floor(world/cell_size)`). 터치/마우스/패드 멀티모달.
- **보드**: `GridBoard` = `Dictionary[Vector2i → CellState]`. CellState = { kind: DIRT|TREASURE, treasure_id, revealed, excavated, damaged, number }.
- **캐스케이드**: BFS 플러드필 — 0칸에서 인접 흙칸으로만 전파(보물칸 자동 개방 불가 → 사고 파손 없음).
- **레벨 생성 (절차 생성 우선)**: 무작위 배치 → 계층형 논리 솔버(T1/T2/T3, +의뢰서/모양인지 모드)로 노-게스 검증 → 통과 보드만 채택(rejection sampling), 실패 시 국소 수정. 시드 기반(일일·공유·테스트 결정성). 소수의 저작 마일스톤 레벨 병행. (상세는 아래 「개발 계획」의 모듈 구성)
- **점수·별점 (4-카운터)**: `original(보물 총수)` = `clean(온전)` + `damaged(파손)` + `missed(미발굴)`. 점수 = 온전 가치 합 − 파손 패널티. 별점: 1★ 보물 ≥1, 2★ 온전 ≥ X%, 3★ 전부 온전·무파손.
- **도감/박물관**: 보물 종류별 엔트리. 온전 획득 → 전시. 파손 → "복원 필요" 상태.
- **진행**: 5×5 → 점진 확대. 챕터 = 발굴 지역(캠페인 매니페스트 잠금). (후순위) 절차적 "끝없는/일일 발굴" 모드.
- **레벨 저작 도구**: 아이패드용 웹 에디터(.tres 익스포트) 개념을 보물 배치/발굴권/도감 매핑용으로 개조.

## 기술: 재사용 vs 신규 (CandyAnts 기반)
**재사용** (CandyAnts → 새 프로젝트로 시드 복사): `EventBus`, `Motion`(boop/caPop/fade), `SfxPlayer`·`BgmPlayer`(ID 교체), `Strings`(한글), `Tokens`(색), `CButton`, `StageSelect`/별점, `SaveData` 4-카운터, `Campaign`/매니페스트, `InputRouter`/`CoordSpace`, `SceneFlow`(상태명 교체).

**신규**: `GridBoard`(2D Dictionary + BFS 캐스케이드), `GridCell` 씬·스크립트, 노-게스 생성/검증 솔버, 발굴권(`ExcavationBudget`), 보물/도감 데이터(`TreasureData`·`DigStageData` .tres), 박물관 화면.

**배치**: `godot/TreasureDig/` (CandyAnts 형제). Godot 4.6. 코드 직접 공유 금지 — 시드 복사 후 독립 운영.

## 개발 계획

> CandyAnts MVP의 "스테이지별로 코드를 짜다 공통 시스템이 누더기가 된" 문제를 피하려, **모듈·계약을 먼저 고정**하고 **레벨을 코드가 아닌 데이터(`GenParams` 프리셋)로** 다룬다.

### 모듈 구성 (계층 · 단방향 의존)
- **L0 데이터/도메인** (노드 의존 X, 순수·테스트 용이): `ShapeDef`·`TreasureDef`·`RegionDef`·`GenParams`·`CellState`·`BoardModel`·`Placement`·`GeneratedLevel`(풋프린트)·`SkinnedLevel`(스킨 배정)·`SolveResult`, `ShapeCatalog`·`TreasureCatalog`(.tres 폴더+인덱스).
- **L1 생성 파이프라인** (순수 로직, 시드로 결정적 → 헤드리스 테스트): `ShapeBudgetPlanner` → `TreasurePlacer` → `NumberComputer` → `Solver`(T1/T2/T3 + 의뢰서/모양인지) → `BoardGenerator`(오케스트레이션·국소수정) / `SpawnWeighting`(확률 가중 순수함수) → `TreasureDistributor`(풋프린트→보물 스킨) / `BudgetCalculator` / `Rng`(시드).
- **L2 런타임** (노드): `BoardController`(캐스케이드 BFS)·`GridCell`·`ToolController`·`ScoreSystem`(4-카운터).
- **L3 메타/저장**: `CollectionService`(도감·갭필)·`SaveData`(재사용)·`Campaign`/지역 진행(재사용).
- **L4 UI**: HUD·MuseumScreen·LevelSelect·ResultDialog (`CButton`·`Motion`·`StageSelect` 재사용).
- **교차 관심사**: `EventBus`·`Sfx/BgmPlayer`·`Strings`·`Tokens`·`InputRouter`/`CoordSpace` (전부 재사용).

**핵심 계약(이음새)**: `BoardGenerator.generate(GenParams, rng) → GeneratedLevel` → `TreasureDistributor.assign(level, collection, rng) → SkinnedLevel` → `BoardController.load(SkinnedLevel)` → EventBus 이벤트(`cell_revealed`·`treasure_excavated`·`treasure_damaged`·`budget_changed`·`level_complete`)를 ScoreSystem·CollectionService·UI가 구독. 의존은 **L4→…→L0 단방향, 순환 금지.**

### 2계층 분배 & 등급 (수집 동기 엔진)
- **풋프린트(모양)=난이도, 스킨(보물)=수집** 으로 분리 → 솔버는 모양만, 도감은 자유.
- 같은 칸 수에 **여러 모양 × 여러 등급**. 등급↑ = 등장 확률↓(전설 희귀) → 반복 플레이 동기.
- 등급은 **순수 스킨/수집**(난이도·별점과 분리). 8살 안전장치: 소프트 피티·갭필 우선·유한 도감(40~60종)·결제 없음.

### 난이도 = 맵크기(소/중/대) × 비율(쉬움/보통/어려움)
- 비율(밀도)이 주 노브, 요구 추론등급·발굴권 슬랙이 자동 동반.
- **대형 보물 게이팅(파생)**: `N ≤ 최대모양(난이도) ∧ 보물칸예산 ≥ N+2` → 대형 유물은 큰 맵·고난도에서만 자연 등장(= 엔드게임 수집 목표).

### 페이즈

| P | 목표 | 핵심 모듈 | 데모 |
|---|---|---|---|
| **P0** 스캐폴드·계약 | 뼈대 + L0 타입·계약 + 카탈로그 스켈레톤 + 코어 시드 복사 | 오토로드(EventBus·SaveData·Rng…), L0 전 타입 | — |
| **P1** 코어 루프 수직슬라이스 | 하드코딩 `SkinnedLevel`로 곡괭이·숫자·캐스케이드·발굴·발굴권·점수 (생성기 X) | BoardController·GridCell·ToolController·ScoreSystem | 🎯 첫 플레이 가능(재미 검증) |
| **P2** 생성 파이프라인 | `GenParams→검증 레벨`. 작은 솔버로 타당성 확인 후 전체 구축 | NumberComputer·Solver·Placer·BoardGenerator·BudgetCalc·Rng | 🎯 첫 생성 레벨 |
| **P3** 분배·등급·**기본 콜렉팅** | 풋프린트→보물 스킨(확률) + 최소 수집 저장·박물관 껍데기 | SpawnWeighting·TreasureDistributor·CollectionService(기본)·SaveData 확장 | 🎯 첫 수집물(희귀 등장) |
| **P4** 난이도 매트릭스·지역·진행 | 소/중/대 × 쉬움/보통/어려움 프리셋, 지역 풀, 잠금·레벨선택 | GenParams 프리셋·RegionDef·Campaign(재사용)·대형 게이팅 | 🎯 첫 캠페인 |
| **P5** **콜렉팅 디테일** | 다채로운 보물 콘텐츠 위에 도감 UI/UX 전면 개편 + 메타 루프 | CollectionGoals(지역세트·완성%)·완성 보상·중복·복원·인스펙트·박물관 재설계 | 🎯 수집 동기 엔진 완성 |
| **P6** 폴리시·웹 | 연출·의뢰서 UI·SFX/BGM·웹빌드·**8살 플레이테스트** | ResultDialog·의뢰서 패널·build_web.py | 🎯 출시 후보 |

- **콜렉팅은 P3(기본) → P5(디테일)로 분리**: 초반엔 루프가 보상받을 최소 수집만, 보물 콘텐츠가 다채로워진 뒤 후반에 UI/UX 개편·메타 루프를 별도로.
- **두 트랙은 `SkinnedLevel` 계약으로만 접속** → P1(재미)과 P2(생성)는 순서 교환·병렬 가능. 권장: 재미 먼저, 위험(생성) 다음.

### 콘텐츠 저작 트랙 (데이터, 병렬 — 코드 페이즈 아님)
- 보물은 데이터(.tres). P2·P3는 **씨앗 카탈로그(소수)**로 테스트, 본 카탈로그(40~60종 × 모양·등급·지역·아트)는 P3~P4에 저작해 **P5 개편의 재료**로 투입.
- **TreasureCatalog 에디터**(CandyAnts 웹 에디터 방식)로 코드 없이 양산.
